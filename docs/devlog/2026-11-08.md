## 결정
- **휴대폰은 `schema_version` ≥ 1(PC v1.8.0 이상) 파일만 받음**: 예전 구조 보완(마이그레이션)은 PC 가 맡아 JS 로 옮길 코드를 줄임. 예전 파일이면 "PC 를 v1.8.0 이상으로 실행한 뒤 다시 내보내기" 안내
- 불러오기는 '수정'이 아니므로 파일의 `last_modified` 를 그대로 유지 (PC 복원과 동일)
- 불러오기 직전 장부를 IndexedDB `before_import` 에 1개 보관
- `vendor/sql.js/package.json`(`commonjs`): 저장소가 `"type": "module"` 이라 Node 테스트에서 sql.js 를 CommonJS 로 읽게 함 (브라우저 영향 없음)

## 검증

# 백업 보내기 · 7일 알림 (v0.3.0)

| 구분 | 내용 |
|---|---|
| 구현 | `js/db/backup.js`(보내기·알림 판단), `js/views/home.js`·`backup.js`, `js/state.js`, 아래 탭·알림 창 |
| 테스트 | 31개 통과 |

## 결정
- **공유 → 안 되면 다운로드**: 안드로이드 크롬의 Web Share 는 공유할 수 있는 파일 종류(사진·PDF·txt 등)가 정해져 있어 `.db` 는 막힐 가능성이 큼. `canShare` 로 확인해 안 되면 다운로드 폴더에 저장하고 카카오톡 첨부 방법을 안내. **실제 갤럭시에서 어느 쪽이 되는지 확인 필요**(8단계)
- **알림 조건**: '휴대폰에서 고친 내용이 백업 후 7일 넘게 밖으로 안 나감'. 날짜만 보지 않는 이유: 바뀐 게 없으면 이미 안전하므로 매주 같은 알림을 띄울 필요가 없음
- **불러오기 = 백업 시점**: 불러온 파일은 보낸 쪽(PC·카톡)에 그대로 있으므로
- 마지막 백업 시각은 장부 밖(IndexedDB `meta`)에 저장: 장부에 쓰면 그 자체가 '수정'이 되어 알림이 꺼지지 않음
- 되돌리기는 지금 장부와 보관본을 **맞바꿈** → 되돌리기를 다시 되돌릴 수 있음

## 검증 (Edge 헤드리스 + DevTools, 390×844, 빈 포트 8766/9555 사용 후 내가 띄운 것만 종료)

## 결정
- PC 의 '표에서 바로 수정'은 휴대폰에서 칸이 작아 불편 → **카드 + 아래에서 올라오는 입력 창**
- [납부 완료] 한 번의 입금일: 이번 달이면 오늘, 지난·다음 달이면 1일 (PC 표는 1일. 휴대폰은 현장에서 받는 경우가 많아 오늘)
- 입력 창은 저장 실패 시 닫지 않고 그 안에 오류(업무 규칙의 문구 그대로) → 입력한 값을 잃지 않음
- 데이터 초기화·전체 삭제는 휴대폰에서 제외(실수로 전부 지우는 것 방지)
- 연락처는 목록에서 가운데 4자리 가림, 수정 창에서만 전체 표시

## 검증 항목
- 회비: [납부 완료] → 입금 1건 생성 / 카드 → 면제 → 연결 입금 삭제 / 금액 0 → 창 안 오류·창 유지 / 필터·월 이동 / 선납 3개월(면제 달 건너뜀 미리보기) → 공유 입금
- 통장: 빈 거래 오류 / 등록 → 목록 / 수정(금액) / 삭제
- 회원: 등록(연락처 형식 맞춤·등번호) / 목록 가림 / 등번호 중복 오류 / 휴면 → 활동 목록에서 빠짐 / 검색
- 팀 설정: 블루로 → 상단 색 / 새로고침 후 색·기록 유지 / 마지막 수정 기기 = 휴대폰
